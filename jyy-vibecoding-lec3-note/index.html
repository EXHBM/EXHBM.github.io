（有 best practice）

每次！记录改动！

Tips：学会追问

线上每个圈 ＝ 一个版本节点（V1 / V2 / V3）；两点之间 ＝ 一次 commit，写的就是这次 commit 的 message；V2 下面挂的括号 ＝ 给某个版本打的 Tag；左右两端都能继续 commit。

commit message 按 Git 惯例写：type: 说明，常用 feat（新功能）/ fix（修 bug）/ docs / refactor / chore；用祈使句（Add… 而不是 Added…），首行 50 字符以内，末尾不加句号。也就是 git commit -m "fix: prevent crash on load" 这种。

1.4 Git 的优势

  • 避免版本库膨胀 —— 不带构建产物（V1、 V2各自构建一个文件夹的方式会带构建产物，但是如果用了Git就可以把构建产物单独放在Git外的文件夹里面汇总。）

注： git 里不要 add 构建产物 —— 协作者环境不同就会有问题

  • 版本可回溯　·　功能丰富、效率高（甚至可以对接 gh、gitlab 等）

1.5 Git with AI Agent

现在是 Agent-Native 时代， 只要有概念能干什么， 就能让 Agent 做。

But 问题是 → 是你自己能干，还是离了 Agent 你就干不了了

↳ 解法： 与 Agent 协作，学习 best-practice，用到真正的工程中！
